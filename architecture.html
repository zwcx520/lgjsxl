01

系统总览

SYSTEM OVERVIEW

力哥健身训练系统是一款纯前端单页应用（SPA），采用原生 HTML/CSS/JavaScript 构建， 无需任何后端服务器，所有数据通过浏览器 localStorage 本地存储。 系统覆盖训练管理全流程，包含 12 个功能模块、56+ 训练动作、6 套训练计划。

核心设计理念

零后端、零数据库、零云服务 —— 所有业务逻辑和数据持久化完全在用户浏览器中完成，隐私数据不出设备。

分层架构

LAYERED ARCHITECTURE

系统采用经典的四层架构，从上到下依次为：表现层 → 逻辑层 → 数据层 → 存储层。 每层职责单一，通过函数调用衔接。

LAYER 1
表现层 · Presentation Layer
HTML结构 + CSS样式 + SVG图形，负责界面渲染与用户交互
index.html (SPA容器) styles.css (主题+布局+组件) SVG人体图 模态框系统 Toast通知 响应式断点
LAYER 2
逻辑层 · Logic Layer
app.js 核心应用逻辑，函数式编程，DOM操作驱动渲染
navigate() 路由切换 render*() 12个渲染函数 finishSession() 训练完成处理 calc*() 计算器引擎 checkAchievements() 成就检测 toast() 通知系统 openModal/closeModal 模态框
LAYER 3
数据层 · Data Layer
data.js 静态数据库 + state 运行时状态对象
EXERCISE_DB (56+动作) TRAINING_PLANS (6套计划) MEAL_PLANS (3套饮食) ACHIEVEMENTS (11项成就) state对象 (运行时状态) activeSession (训练会话)
LAYER 4
存储层 · Storage Layer
浏览器 localStorage 持久化，JSON序列化，零网络传输
forge_fitness_data (主数据) forge_active_session (训练会话) app_tip_version (欢迎弹窗版本) JSON.parse / JSON.stringify
04

数据流

DATA FLOW

系统采用单向数据流：用户交互 → 更新 state → 保存 localStorage → 重新渲染 DOM。 训练会话独立存储，支持刷新不丢失。

训练会话独立存储

训练过程中每次修改重量/次数都会自动调用 saveSession() 写入 forge_active_session，刷新页面后自动恢复，训练完成时清除该键。

数据模型

DATA MODEL

运行时状态由全局 state 对象管理，包含个人资料、训练记录、身体数据、PR、成就等。 训练会话由独立的 activeSession 对象管理。

state (主状态对象)

state = {
  profile: {
    name: 'FORGE',
    gender: 'male',
    age: 25, height: 175,
    weight: 70,
    goal: 'bulk',
    level: 'beginner'
  },
  // ... 见右侧其他模型
}

存储在 forge_fitness_data 键中，每次修改后调用 save() 持久化。

workouts[] (训练记录)

{
  id: 'lmx...',
  date: '2026-08-09',
  name: '推日A',
  planId: 'ppl',
  duration: 3600,
  exercises: [{
    id: 'ch1',
    name: '杠铃卧推',
    sets: [{
      weight: '80',
      reps: '8',
      done: true
    }]
  }]
}

每次完成训练时 push 到 state.workouts 数组。

measurements[] (身体数据)

{
  date: '2026-08-09',
  weight: 72.5,
  bodyfat: 15.2,
  chest: 98,
  waist: 82,
  arm: 36,
  thigh: 55
}

用于体重曲线图和围度表格展示。

prs (力量PR)

prs = {
  bench: 80,    // 卧推
  squat: 100,   // 深蹲
  deadlift: 120, // 硬拉
  opress: 50,    // 推举
  row: 70       // 划船
}

卧推/深蹲/硬拉训练时自动检测，推举/划船手动记录。

activeSession (训练会话)

{
  id: 'uid...',
  date: '2026-08-09',
  name: '推日A',
  planId: 'ppl',
  startTime: 1723...',
  exercises: [{
    id: 'ch1',
    targetSets: 4,
    sets: [
      {weight:'', reps:'', done:false}
    ]
  }]
}

独立存储在 forge_active_session，训练完成时清除。

08

存储机制

STORAGE MECHANISM

所有数据通过浏览器 localStorage 存储，JSON 序列化/反序列化。 3 个存储键各司其职，零网络传输。

用户操作
输入/点击/提交
state 更新
内存对象修改
JSON.stringify
序列化
localStorage
setItem(key, json)
forge_fitness_data

主数据键。存储所有训练记录、身体测量、PR、成就、个人资料、自定义内容。每次状态变更后由 save() 写入。

JSON · 永久存储
forge_active_session

训练会话键。存储当前进行中的训练会话，支持刷新恢复。训练完成时由 saveSession() 清除。

JSON · 临时存储
app_tip_version

欢迎弹窗版本号。由 syfw.js 管理，版本号变更后所有用户下次打开重新弹窗。

String · 永久存储
核心函数

load() — 启动时从 localStorage 恢复 state
save() — 状态变更时持久化 state
saveSession() — 训练会话自动保存/清除

3 个核心函数
隐私安全

localStorage 数据不随 HTTP 请求发送到服务器，受浏览器同源策略保护，其他网站无法访问。数据完全在用户设备本地，开发者也无法访问。
